# ESP32-S3 终端固件（HCP/1 参考实现）

本目录是「万物之城」硬件终端的参考固件：把一块 **ESP32-S3 + SPI 小屏 + 5 个按键** 变成游戏的第二操控屏。
固件本身不含任何游戏规则，全部语义由服务器下发的 HUD 帧决定（见 `docs/hardware/HCP-v1.md`）。

> 状态说明：服务端与协议已通过 `tests/hardware.test.ts` 的 19 项端到端用例（模拟设备）。
> 本目录固件为**参考实现，尚未在真机上编译烧录验证**——首次上板时请按下面顺序排查，不要当成已验证交付。

## 一、你需要改的东西（只有 `include/config.h`）

| 宏 | 填什么 | 示例 |
| --- | --- | --- |
| `DEFAULT_WIFI_SSID` | 校园/实验室 Wi-Fi 名称（需 2.4GHz，ESP32 不支持 5GHz） | `"Campus-IoT"` |
| `DEFAULT_WIFI_PASS` | Wi-Fi 密码 | `"12345678"` |
| `DEFAULT_SERVER_HOST` | **只填域名**，不带 `https://`、不带路径 | `"iot.luo-jin-ai.com"` |
| `DEFAULT_SERVER_PORT` | HTTPS 端口，通常 443 | `443` |
| `DEVICE_MODEL` | 设备型号，会显示在网页「我的终端」 | `"ESP32-S3-TFT-320x240"` |

可选：

| 宏 | 说明 |
| --- | --- |
| `PROVISION_KEY` | 批量烧录密钥，需与服务器环境变量 `HW_ENROLL_KEY` 一致；未配置服务器则不填 |
| `DEVICE_TLS_VERIFY` | `0` 跳过证书校验（校园内网可用）；`1` 需填好 `src/ca_cert.h` |
| `PIN_TFT_*` / `PIN_KEY1..5` | 引脚，按自己的板子改 |

改完直接 `pio run -t upload` 即可，**不需要**在代码里写设备号、令牌或配对码——首次开机自动登记并显示配对码。

## 二、首次开机流程

1. 上电 → 串口 115200 打印型号与固件版本，屏幕显示「正在初始化」。
2. 固件用 `config.h` 的 Wi-Fi 连接网络（失败则提示用串口配置）。
3. 自动 `POST /api/hw/enroll` 登记，拿到**设备令牌**（存 NVS）与 **8 位配对码**。
4. 屏幕显示 `ABCD-2345` 形式的大字配对码。
5. 学生在网页「我的终端 → 添加终端」输入该码 → 服务器把设备绑定到账号。
6. 终端收到 `ready` 帧，显示「已绑定，等待选择任务」。
7. 学生在网页开始一关 → 终端自动挂载该会话，变成操作面板。

配对码 10 分钟有效；未绑定设备 24 小时后自动作废，重新上电或 `reset` 可再生成。

## 三、串口配置命令（115200，带换行）

```
help                      显示全部命令
status                    查看型号/固件/设备号/Wi-Fi/服务器/通道状态
wifi <ssid> <password>    设置并保存 Wi-Fi，随后自动重启
server <host> [port]      设置服务器域名（自动去掉 https:// 与结尾斜杠）
enroll                    清除令牌后重新登记，生成新配对码
reset                     恢复出厂（等同于 enroll）
```

`status` 输出会打码令牌（只显示「已保存」），不会泄露凭据。

## 四、接线（默认引脚，可在 config.h 修改）

| 信号 | GPIO | 说明 |
| --- | --- | --- |
| TFT SCLK | 12 | SPI2 时钟 |
| TFT MOSI | 11 | SPI2 数据 |
| TFT CS | 10 | 片选 |
| TFT DC | 9 | 数据/命令 |
| TFT RST | 14 | 复位 |
| TFT BL | 13 | 背光（PWM） |
| K1–K5 | 4 / 5 / 6 / 7 / 15 | 按键另一端接 GND，内部上拉 |

屏幕驱动默认 **ST7789 320×240**，若使用其他驱动（GC9A01 圆屏、ILI9341 等）只需替换 `src/hud_render.cpp` 顶部的 `lgfx::Panel_*`。
中文字形使用 LovyanGFX 内置 `efontCN_12/16`，无需额外取模。

## 五、按键语义从哪来

服务器在每一帧 HUD 里下发 `km` 数组，例如：

```json
"km": [
  {"k":"K1","lb":"检查设备","cmd":"inspect","tg":"sensor-1","tone":"primary"},
  {"k":"K2","lb":"下一设备","nav":"focus-next"},
  {"k":"K3","lb":"仿真1秒","cmd":"simulate","pl":{"ticks":1}}
]
```

- 固件只上报 `{"t":"input","id":"...","ev":{"t":"key","k":"K1"}}`；
- 服务器按自己保留的映射表翻译成游戏命令，并按引擎规则校验；
- 不在映射表里的按键会被拒绝（`UNKNOWN_KEY`），所以刷改固件也无法越权操作。

屏幕尺寸不同不影响协议：服务器按 `caps.keys` 数量裁剪按键、按 `w/h` 调整文本长度。

## 六、常见问题

| 现象 | 排查 |
| --- | --- |
| 卡在「Wi-Fi 未连接」 | 确认是 2.4GHz；企业级 802.1X 网络不支持，先换普通 WPA2 |
| 登记失败 `status=401` | 服务器配了 `HW_ENROLL_KEY`，需要在 `config.h` 填 `PROVISION_KEY` |
| 登记失败 `status=0` | 明文 HTTP 端口被拒；确认用 443 且服务器有 TLS |
| 屏幕显示配对码但网页提示无效 | 配对码 10 分钟过期，执行 `enroll` 重新生成 |
| 绑定后仍显示「等待选择任务」 | 网页要先开始一关；终端只接管进行中的个人会话，联机房间需在浏览器操作 |
| 操作无反应 | 看串口是否打印 `[key] ...`；有打印则看服务器返回的 `err` 码 |
| 频繁 `RATE_LIMIT` | 协议限 10 次/秒、300 次/分，按键抖动未消抖也会触发 |
| 时间/得分显示不动 | 服务器每 1.2 秒推一次帧，只在内容变化时更新；断线会显示「连接中断」 |

## 七、安全边界（务必知悉）

- 设备令牌是**长期凭据**，只存在 NVS 中；`reset` 或网页解绑会立即让旧令牌失效。
- 未开启 `DEVICE_TLS_VERIFY` 时链路可被中间人窃听，**只建议在校园内网实验台使用**；公网部署请开启并配置 CA。
- 固件只能触发服务器白名单内的命令类型（`start/pause/resume/inspect/dialog/simulate/hint/answer`），且必须落在服务器下发的按键映射内。
- 硬件传感器读数（`sensor` 帧）在 v1 仅作观测对照，只在非标准挑战的自由沙盒中接受，不参与计分。
