# 万物之城 Implementation Plan

> **For agentic workers:** Execute task-by-task using the user's prescribed Codex + local OpenCode CLI workflow; independent worktrees, Codex integration. User explicitly requests autonomous execution after the concise architecture, so do not add another approval gate for routine implementation.

**Goal:** 完成并在Server2部署60关、九模式、真实多人和教学运营平台。
**Architecture:** React/Three.js 同源Node HTTP/WebSocket服务，共享纯确定性引擎，独立MySQL库保存事务快照、事件和不可变内容版本。Codex维护契约与核心；OpenCode分批实现界面/内容/后台。
**Tech Stack:** TypeScript, React, Vite, Three.js, Fastify, ws, mysql2, Zod, MySQL8, systemd, Nginx。
**Spec:** ../specs/2026-10-21-iot-city-design.md; root PROJECT_REQUIREMENTS.md, CONTRACTS.md, DATABASE.md, GAME_ENGINE_SPEC.md。

## Global Constraints
- 用户确认：Server2、独立简单账号、iot.luo-jin-ai.com。
- 60关有实质工程差异，九模式均真可玩；不以假数据、空入口或计划冒充完成。
- 独立目录/数据库/内网端口，保护所有已有服务。部署仅Codex执行；不改金融系统。
- 教师DSL安全、版本绑定、服务器权威结算、重试幂等、数据权限隔离。
- 完成测试与实际浏览器验收，逐项保留边界和证据。

## Review Focus
- 重复或并发命令不能重复奖励或覆盖较新存档（核心事务/结算测试）。
- 教师发布新版本后旧存档仍能恢复（版本兼容测试）。
- 被禁用/改角色用户的旧Cookie和WebSocket失效（鉴权测试）。
- 种子任务的设备、目标和解法仍匹配（全关solution与生成器测试）。
- 房间重连/退出/掉电必须可恢复且不重复结算（多浏览器与持久化恢复测试）。
