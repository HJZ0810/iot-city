# 万物之城：物联网沉浸式教学游戏平台

## 已确认的目标
面向高校物联网学生，用探索、设备连接、配置、仿真、排障与多人协作推动剧情。正式规模60关、九模式、真实联机、可跨设备恢复的存档，以及教师能够创建并发布可玩新关卡的运营平台。完整需求以 PROJECT_REQUIREMENTS.md 和源文件为准。

用户选择：独立用户名密码账号；域名 iot.luo-jin-ai.com；部署 Server2。所有原文中 server1 的分工示例均按 Server2 执行。

## Codex 作出的实现选择
- 品牌：万物之城 / NEXUS CITY。用户未指定品牌，可独立调整，不影响数据ID。
- React、TypeScript、Vite 为表现层；Three.js 延迟加载实际可操作3D场景，Canvas/SVG拓扑与2.5D实验台复用同一状态模型。
- Fastify 模块化后端＋同进程 WebSocket 权威房间，避免服务器额外微服务开销。关系库采用现有 MySQL 8.0.46 的独立数据库 iot_city，评估 PostgreSQL 后选择减少额外常驻进程的方案。
- Linux Node 22。服务器运行产物在本机构建，生产机只安装生产依赖；systemd 控制内存与CPU；端口127.0.0.1:3220为候选，部署时重新检查。
- 不用Redis作为初始必需依赖。在线房间可重建，所有被确认的关键游戏状态写事务；单实例房间执行串行队列，保证事件顺序。
- 本地工程 D:\PRO\iot-city-20261021；正式 /opt/iot-city/releases/<id>，运行数据 /var/lib/iot-city，配置 /etc/iot-city；数据库凭据不进入Git。域名独立Nginx配置，不重用其他站点location。

## 产品与视觉
主视图是可探索的未来城市与章节入口，主行动是继续最近任务。深蓝石墨背景、温暖象牙文字、青绿设备状态和少量橙色告警；不使用巨幅营销头图或满屏信息卡替代游戏。空间具有城市街区、温室、工厂、机房等差异，角色对话与设备异常在场景中触发。

游戏界面：场景占主要面积，任务和设备属性可收起；拓扑连线支持键盘选择两端和拖拽；参数允许数值、枚举、开关。移动端使用面板抽屉和分步连线。音频默认不自动播放，可显式开启。提供低特效/2D模式、减少动画和页面隐藏时暂停视觉资源。

教师界面以班级、作业、学生进度、回放、内容编辑为核心。管理员管理账号角色、全局内容审核、赛季、资源、审计和运行信息。常规学生注册不能获取高级角色。

## 程序边界与共享契约
- packages/shared：唯一的内容Schema、命令类型、模式/角色、API数据格式。
- packages/engine：纯确定性状态机、受控规则、设备/网络/环境仿真、评分、种子挑战；不依赖HTTP、浏览器或数据库。
- packages/content：60关的完整数据、10章剧情、NPC、专业知识、资源来源；内容由Schema校验并有每关解法与失败路径。
- apps/web：学生/教师/管理员表现层，真实API，无硬编码虚构榜单。
- services/api：认证、班级/作业/内容、游戏会话、存档/事件/结算、实时合作和竞技、报表/审计。
- deploy、scripts、tests：可复现部署、备份恢复、验收与证据。

## 权威游戏循环
客户端只提交操作命令与预期修订号。服务器校验用户、会话、角色、对象、参数和阶段，在事务内读取当前快照并加锁，运行纯引擎，持久化新快照与唯一事件。相同commandId重试返回原确认；旧修订号返回冲突快照，不能覆盖新进度。

会话绑定关卡不可变版本；教师发布产生新版本，旧会话继续读旧内容。成功由目标谓词与仿真状态计算。客户端不能提交分数/完成状态。结算唯一约束防止重复奖励。时间成绩使用服务端有效活动时间；暂停不推进单人仿真；竞技不因个人暂停停止。

命令涵盖探索、对话、取用道具、安装/拆卸、连接/断开、配置、控制规则、分析、启动仿真。设备参数按定义校验，DSL仅可引用已知设备/环境/任务字段，禁止eval。仿真明确是教学抽象：传感器误差与校准、ADC采样、PWM、总线地址/速率匹配、协议订阅/QoS、链路可达性和控制规则等都要有真实因果行为。

事件记录保存必要输入、输出摘要、序号与服务器时间，按快照+事件重建；回放读取路径绝不能调用正式写入/结算路径。回放支持暂停、速度和跳转，教师只访问所属班级数据。

## 模式与评分
剧情60关按章节解锁；无尽/每日/随机由种子和已验证模板生成；限时使用服务端计时；自由沙盒保存工程，不计入竞争总分，标准挑战单独结算；Boss多阶段；合作默认2–4人可配置；竞技支持1v1和2v2的相同种子、独立队伍状态。

综合积分采用各模式有上限的最佳有效成绩归一化，区分个人、团队和赛季；游戏分数是教学表现，不是金融积分。无尽无法无限累加总榜。每日日期按Asia/Shanghai服务端计算，可配置刷新小时。竞技胜负与匹配评分只在服务器提交。

## 数据及账号
Users/Roles/Sessions、Classes/Members/Assignments、Teams/Members、Chapters/Levels/Versions/Knowledge、GameSessions/Snapshots/Events/Results、Inventory/Achievements、Rooms/Matches/Participants、Rankings/Seasons/DailyChallenges、Assets/ContentAudit/SystemAudit 均有隔离与索引。

密码安全哈希，HttpOnly/SameSite Cookie，同源写入校验，登录限流、会话撤销和过期；简单账号不添加邮箱短信依赖。教师账号由管理员授予；学生可通过邀请码加入班级。重置密码撤销旧会话。操作事件默认保留180天，结果/成绩保留直到账户删除或管理员清理；UI告知，支持授权导出。

## 部署保护与性能验收
已观察：Ubuntu24.04.1、8核、7939MiB内存、约4.2GiB可用、磁盘剩余约7.4GB、46个运行systemd服务、已有MySQL8.0.46、Node22.23.2。Nginx现有protocol options警告但语法通过；不把已有警告算作本工程故障。

只增加独立数据库/最小权限账号、新systemd单元和iot域名配置。变更前记录现有站点/配置散列与健康基线；配置备份后nginx -t再reload；不重启已有业务。证书必须能真实签发和浏览器信任。回滚仅切换本工程release并保留数据库和玩家数据。

初始性能验收目标由Codex提出：30并发用户、8合作房间的隔离测试；API常规请求p95<300ms、命令确认p95<500ms、桌面可交互场景目标45fps以上。它们是待测目标，不是承载保证；测试严格设限，避免影响既有业务。长稳与容量报告写实测持续时间和环境。
